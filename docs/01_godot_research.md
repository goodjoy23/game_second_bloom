# Godot 공식 사이트 요약과 1인 개발 방향

작성 기준일: 2026-08-24

## 공식 사이트 핵심 요약

Godot은 2D, 3D, XR과 여러 플랫폼 배포를 지원하는 자유·오픈소스 게임 엔진이다. 공식 사이트는 노드와 씬을 조합하는 구조, 전용 2D 파이프라인, GDScript 및 C# 지원, 데스크톱·모바일·웹 배포를 주요 강점으로 소개한다.

- 노드와 씬: 화면, 인물, 대화창, 선택지처럼 재사용할 요소를 작은 장면 단위로 분리하기 좋다.
- GDScript: Python의 영향을 받은 간결한 언어이며 엔진과 밀접하게 통합된다. 선택적 정적 타입도 지원한다.
- 2D와 UI: 실제 2D 좌표 기반 파이프라인과 유연한 GUI 시스템이 있어 비주얼 노벨 제작에 잘 맞는다.
- 다중 플랫폼: 같은 프로젝트를 데스크톱, 모바일, 웹으로 확장할 수 있다.
- 라이선스: 엔진은 MIT 라이선스다. 제작한 게임 콘텐츠의 저작권은 제작자에게 남는다. 배포물에는 Godot 저작권 고지와 라이선스 문구를 포함해야 한다.
- 현재 공식 홈페이지에 표시된 최신 안정판은 4.7.2다. 실제 개발 시작 시에는 플러그인 호환성을 확인하고 프로젝트 전체에서 한 버전을 고정한다.

## 이 프로젝트에 적합한 이유

이 작품은 복잡한 3D 물리보다 대화, 초상화, 배경 전환, 상태값, 저장·불러오기가 중요하다. Godot의 강점과 잘 맞는 범위다.

| 필요 기능 | Godot 적용 |
|---|---|
| 대화 장면 재사용 | `DialogueScene`을 하나 만들고 데이터만 교체 |
| 인물 표정 변화 | `CharacterPortrait` 씬의 텍스처 교체 |
| 선택지와 상태 변화 | GDScript 딕셔너리 또는 커스텀 Resource 사용 |
| 주간 일정 | 달력 UI와 이벤트 조건 테이블 연결 |
| 저장·불러오기 | 상태값을 JSON 또는 Resource 기반 저장 데이터로 직렬화 |
| PC·웹 체험판 | 동일 콘텐츠를 플랫폼별 내보내기 설정으로 배포 |

## GDScript를 우선하는 이유

공유된 제미나이 기록의 결론처럼 이 프로젝트는 GDScript로 시작하는 편이 적합하다. 이유는 서사 데이터와 UI를 빠르게 반복 수정해야 하고, 1인 개발에서 빌드 구조를 단순하게 유지하는 이점이 크기 때문이다.

C#은 이미 숙련되어 있거나 대규모 외부 .NET 라이브러리가 필수일 때 검토한다. Godot 4의 C# 웹 지원에는 공식 사이트가 여전히 제약을 명시하고 있으므로 웹 체험판이 목표라면 GDScript가 더 안전하다.

## 권장 최소 기술 구성

- Godot 4.x 안정판 한 버전 고정
- GDScript 정적 타입 표기 사용
- 해상도: 1920×1080 기준, `CanvasItem` 및 Control 앵커로 대응
- 데이터: 에피소드별 JSON 또는 커스텀 Resource
- 저장 슬롯: 자동 저장 1개 + 수동 저장 10개
- 접근성: 글자 크기 3단계, 자동 진행 속도, 대화 기록, 효과음·음악 개별 음량
- 버전 관리: 텍스트 기반 시나리오와 게임 데이터를 함께 관리

## 1인 개발용 범위 제한

첫 완성본은 다음만 구현한다.

1. 민우 시점 공통 루트 3개 섹터
2. 서정 중심 재회 엔딩 1개
3. 배경 8장, 주요 인물 반신 4명, 표정 5종씩
4. 60~90분 분량의 무료 데모
5. PC 우선, 웹은 성능과 폰트 검증 후 추가

보이스 연기, 3D 공간, 복잡한 미니게임, 네트워크 기능은 첫 버전에서 제외한다.
